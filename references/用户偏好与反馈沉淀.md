# 用户偏好与反馈沉淀

制作和修改PPT时读取本文件，并结合当前对话。当前用户最新明确要求优先；历史案例不自动成为所有项目的样式。

## 已明确的制作偏好

- 主题配图不重复使用。同一主体可以在不同场景继续出现，但必须是独立构图；总览图也不能照搬后续页主图。改裁切、镜像、调色不能规避此要求。纯文字、问答指令页可以不配图。
- 用户认可现有照片并只要求修边融合时，保留原图和主体细节，不重新生成人物或场景。水彩/无边融合风格需消除相框、矩形纸底和色差；仅处理边缘过渡，不整体模糊。去重约束不等于修边时必须换图。检查整页效果，尤其深色底上的白边和艺术字底色块。
- 艺术字是可选表达手段，可在任何适合的页面使用，不限制在封面，也不要求封面必须有。字形要和主题、场景及留白协调。用户不接受此前厚重、逐字机械排列、金属渐变和粗描边堆出的标题效果；不要将这类效果作为默认配方。
- 主分支的课程/主题班会封面审美已获认可，应作为实验分支的优先封面基准：左侧两行艺术字与右侧独立场景图形成非对称关系，配暖色编辑式框架和清晰留白。保留视觉关系，不硬编码示例题目、学校或照片；若用户提供不同参考，以新参考优先。实际基准图见`examples/cover_example_final.jpg`，精修结果见`examples/cover_final_v118.jpg`。
- 视觉型作品不宜只有少数图片。`image-led`默认参考覆盖为：1–4页2个、5–8页4个、9–12页6个、13–15页8个；16页以上以8个为起点，每再增加3页至少增加1个独立主题图位。纸纹、图标和标题字形不计入；有生图上限或图表更适合时，用承担叙事作用的原生图示替代并记录原因。
- 实验分支的逻辑性应保留，但每个逻辑动作必须有页面上可见的视觉关系。不要只用漂亮但中性的卡片、圆环和线条包住内容；用路径、对照、因果链、情境图或分步揭示让观众不依赖讲稿也能理解。具体规则见[视觉逻辑与版式完成度](视觉逻辑与版式完成度.md)。
- 审美舒适度已达到主分支水平是实验分支的合格线：同类内容共享稳定网格、页边距、基线和图框比例；关键转折页再改变构图和节奏。不能为了“多样”让每页各用一套散乱版式。
- 版式应有明显节奏变化，不能主要靠同一左右图文布局换边。动画应服务讲解，包括问题、提示与行动步骤的分步揭示；不要只有同一种翻页淡出。
- 创赛重要内容页应饱满：准备足够的主视觉、辅图、机制、证据和标注，组织清楚主次与空间层次，不能以大留白和少量通用卡片代替设计。细节装饰可建立气氛，但不以固定元素数量判定好看；其他方向按自身用途选视觉密度。详见[创赛视觉](../directions/01-创赛/视觉.md)。
- 创赛封面优先使用几乎横贯画面的超大艺术字作为主标题，并精修字形、字距与图片融合；普通粗体放大不算完成。实际风格、用户新参考和可读性优先，不把艺术字强制用于所有封面，亦可用于其他页面。
- 艺术标题默认每个字均为独立可编辑的PPT原生文本框，能单独上下移动；不要用整句或逐字PNG代替，用户明确要求字图时例外。封面去掉功能步骤、冗余说明和不必要标签，仅保留用户需要的标题、背景与必要身份信息。
- 封面要检查字体与整张背景的气质、明暗和构图关系。当前用户创赛封面的标题必须有明显笔锋：能看到起收、尖锋及粗细变化；无笔锋的粗黑体、普通宋体放大不满足要求。有笔锋仍须检查整句辨识与题材适配；逐字独立文本框不能机械摆成等宽等距单字，按字形调整疏密和重心。用户指出不协调时，在保留笔锋的前提下比较字形和组合的实际渲染，不用“已选书法字体”作为验收理由。
- 用户明确要求“重新生图、重新布局”时，应从主题、主视觉与标题空间一起重做；不能延续旧图，仅改字体和文字位置后声称已重构。只要求修边或保留已认可图片时才延续原图，当前明确要求优先。
- 五类用途采用独立的问答、制作顺序、页型和评价；不能只改页数、栏目或颜色后仍调用同一套模板。按主要用途和观众判断/行动选择方向，见[入口](../SKILL.md)。
- 指定WPS时保留可编辑正文、嵌入项目自产素材，并区分写入文件、静态检查和WPS实机放映验证。兼容性不是取消视觉设计的理由。
- 默认自行生成所需素材。自带模板存在且合适时可参考，只有用户明确指定时才填充模板。
- Skill改进保留在用户指定实验分支，当前为`codex/wps-compat-experiment`。主分支不直接修改、不自动合并。

## 在普通交流中如何更新

1. 识别会改变作品的明确要求：禁止重复用图、否定的字体效果、适用位置、版式单调、动画不足、播放环境等。立即更新当前brief和实际制作，不等下一次完整问卷。
2. 区分范围：具体页的标题与尺寸写项目规格；可重复执行的偏好写本文件或对应规范；本次临时风格、AI假设和未经确认的推测不提升为通用规则。
3. 用户授权维护Skill后，将关键反馈改写为“触发条件 → 应做什么 → 如何检查”的短规则，并修正与它冲突的旧条款。用户后续纠正时更新原条款，不不断叠加相反条款。
4. 只记录可复用的制作要求。账号凭据和私人材料应留在用户指定的私有位置。
5. 交付时指出实际修改的规则及文件，明确本地修改、分支提交和实机验证各自状态。是否推送遵从已有授权；没有远程写入授权时保留本地变更，不擅自发布。

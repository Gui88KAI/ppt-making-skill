# 视觉叙事系统

这份 Skill 不能把每一页当成独立海报。先建立一套“视觉圣经”和“上下文账本”，再把它们传给每一页，才能让主题、素材、版式和动效形成同一个作品。

## 一、先建立视觉圣经

在生成第一张图或第一页 PPT 前，先写 `visual_bible`。它是整套作品的唯一视觉源头：

```json
{
  "thesis": "我们用___为___解决___，凭___赢得信任",
  "audience": "评委最在意的判断",
  "story_arc": ["看见问题", "理解代价", "发现机会", "相信方案", "看到证据", "愿意行动"],
  "visual_metaphor": "贯穿全篇的视觉隐喻，例如：从裂缝到闭环",
  "recurring_motif": "每 3–4 页重复一次的形状、光线或物件",
  "palette": {"base": "#071A14", "main": "#2ECF7A", "accent": "#F1C75B"},
  "style": "documentary photography + restrained editorial graphics",
  "camera_language": "低机位、侧逆光、浅景深、主体偏右",
  "subject_identity": "产品的外形、材质、关键部件必须保持一致",
  "material_language": "金属、湿润土壤、磨砂玻璃",
  "no_go": ["无关的泛科技城市", "带文字的 AI 图片", "与项目无关的漂亮人物"],
  "cover_echo": "结尾要回到封面中的同一主体或同一光线"
}
```

视觉圣经至少包含一个“不能被替换的东西”：产品轮廓、人物动作、场景物件、色彩光线或一个数据符号。没有它，整套图只能保持“差不多的风格”，无法形成连续的作品。

## 二、建立上下文账本

每一页都继承上一页的结论，不重新从零解释项目。每页规格必须带这些字段：

```json
{
  "claim": "这一页唯一要让观众相信的结论",
  "evidence": ["事实、数据、来源或待补材料"],
  "question_answered": "它回答上一页留下的什么问题",
  "bridge_from_previous": "上一页最后一句如何落到本页",
  "bridge_to_next": "本页最后一句如何把观众推到下一页",
  "visual_anchor": "本页唯一主角：主体图 / 数字 / 路径 / 引语",
  "visual_state": "主体在本页的状态、角度、距离或阶段",
  "layout_family": "asym_split / diagonal / orbit / staircase / collage / quote / ...",
  "motion": {"lead": "hero", "shared_ids": ["motion:hero", "motion:trail"]}
}
```

制作时维护一份短账本，至少保留：已确认事实、已选风格、待补材料、上一页落点、下一页问题、已经使用过的版式和素材。把账本传给配图提示词和页面生成器，避免“前面说的是机器人，后面突然变成无人机”这类上下文断裂。

## 三、按四轮推进

1. **事实轮**：抽取受众、评分点、事实、来源、不能编造的内容。
2. **叙事轮**：把页面组织成“问题 → 代价 → 洞察 → 机制 → 证据 → 行动”的因果链；标题连读必须像一段话。
3. **视觉轮**：为每个故事节点指定主体、镜头、光线、隐喻、版式和动效状态。
4. **制作轮**：先生成候选素材，再选版式，最后落地 PPT；每完成一页就更新账本。

不要先写完所有文案再给每页随便找图。图像、版式和标题必须共同回答同一个 `claim`。

## 四、每页的完成标准

- 去掉正文后，主图、数字或路径仍能表达本页的方向。
- 标题能回答上一页的问题，而不是重复栏目名。
- 至少有一项证据或明确的“待补”标记。
- 有一个视觉锚点，其他元素都为它服务。
- 下一页可以沿着本页的主体、光线、数字或方向继续移动。

# 视觉叙事系统

按[入口](../SKILL.md)和所选类型组织内容。目标是让文字、图像、构图和讲解顺序共同表达本页目的。

## 最小视觉方案

在项目已有记录中保留配色、字体角色、图像风格、图文关系与禁用效果。可以用`visual_bible`表示，不必另建文件。用户参考优先，字段按需填写。

```json
{
  "thesis": "看见具体的帮助，并选择一件能做到的回应",
  "palette": {"base": "#F6EBDD", "ink": "#452B20", "accent": "#A6402B"},
  "style": "温暖的水彩日常场景",
  "font_roles": {"body": "目标设备可用的中文字体", "accent": "可选短句书法"},
  "material_language": "浅纸纹与柔和边缘",
  "no_go": ["矩形纸底色差", "不可读的装饰字"]
}
```

这是一个班会示例，不是通用配方。涉及同一产品或人物时补充`subject_identity`；需要贯穿物件时使用`recurring_motif`；需要跨页运动时记录相应状态。不要强迫每套作品都有隐喻、固定频率的物件回归或Morph。

## 逐页记录

共用`pages`规格记录`purpose`或`claim`、阅读顺序、主视觉、讲解时间及与前后页的关系。证据字段用于需要事实支持的结论；问题页写参考引导，活动页写可执行指令。艺术字单独校对，正文不藏进生成图片。

图像生成输入可用`examples/visual_manifest.example.json`，它只是从逐页记录中提取的生图需求，不能代替实际图片或完整页序。

## 检查

- 图文是否服务同一目的；删除装饰后，结构是否仍成立？
- 前后页关系能否解释，讨论或情绪停顿是否留有时间？
- 统一风格下是否保持主题图片独立，是否有与内容无关的重复构图？
- 实际代表页是否验证了字体、留白、图片边缘和底色？
- 更新后的图片、文字和点击顺序是否同步到文件、备注和制作记录？

详细完成依据见[代表页与交付验收](代表页与交付验收.md)，不以填满字段判断完成。
